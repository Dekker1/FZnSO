The whole consumer side. For something running in twenty lines, start with the [Quickstart](../../start/quickstart/).

## 1. Open a library

Find one by name, or open a specific file:

<Tabs syncKey="lang">
<TabItem label="Python">

```python
import fznso

lib = fznso.Library.find("gecode")            # newest installed
lib = fznso.Library.find("gecode", "6")       # newest 6.x.y
lib = fznso.Library("/path/to/libgecode.so")  # this exact file
```

</TabItem>
<TabItem label="Rust">

```rust
use fznso::Library;

let lib = unsafe { Library::find("gecode") }?;
let lib = unsafe { Library::find_version("gecode", "6") }?;
let lib = unsafe { Library::new("/path/to/libgecode.so") }?;
```

Opening a library is `unsafe` because it runs the file's initialisers: you are trusting the file.
Everything past this point is safe.

</TabItem>
<TabItem label="C++">

```cpp
#include "fznso.hpp"

std::unique_ptr<fznso::Library> lib = fznso::Library::find("gecode");
lib = fznso::Library::find_version("gecode", "6");
fznso::Library exact{"/path/to/libgecode.so"};
```

</TabItem>
</Tabs>

The ABI version is checked here, before any other entry point is called, so a mismatched solver fails to load rather than crashing later.
If nothing is found, see [Installing solvers](../installing-solvers/).

## 2. Ask what it can do

A library declares its capabilities in [five lists](../../spec/entry-points/#the-library), fixed for its lifetime.
Read them if you need to adapt; skip them if you already know the solver.

<Tabs syncKey="lang">
<TabItem label="Python">

```python
lib.constraint_types()  # identifiers and argument types
lib.decision_types()    # decision-variable types it can create
lib.objectives()        # objective strategies
lib.options()           # options, with types and defaults
lib.statistics()        # statistics, and where each can be read from
```

Each call copies the library's list into ordinary Python objects — `opt.ident`, `opt.argument_type`, `opt.default` — so read them once and keep what you need.

</TabItem>
<TabItem label="Rust">

```rust
lib.constraint_types();  // identifiers and argument types
lib.decision_types();    // decision-variable types it can create
lib.objective_list();    // objective strategies
lib.option_list();       // options, with types and defaults
lib.statistic_list();    // statistics, and where each can be read from
```

</TabItem>
<TabItem label="C++">

```cpp
lib->constraint_types();  // identifiers and argument types
lib->decision_types();    // decision-variable types it can create
lib->objectives();        // objective strategies
lib->options();           // options, with types and defaults
lib->statistics();        // statistics, and where each can be read from
```

</TabItem>
</Tabs>

**Do not pass a name that is not in these lists**, and check the argument *types* too — a solver may accept a constraint only in a [narrower](../../spec/entry-points/#declaring-a-narrower-argument-type) form than the [registry](../../registry/) declares.

## 3. Describe the problem

The simplest route is `LayeredModel`, an in-memory model the bindings provide:

<Tabs syncKey="lang">
<TabItem label="Python">

```python
var_int = fznso.Type("int", decision=True)

model = fznso.LayeredModel()
x = model.add_decision(var_int, range(1, 11), name="x")   # x in 1..10
y = model.add_decision(var_int, range(1, 11), name="y")
model.add_constraint("int_lin_le", [[1, 1], [x, y], 12])  # x + y <= 12
model.add_constraint("int_lin_ne", [[1, -1], [x, y], 0])  # x != y
model.set_objective("int_maximize", x)
```

</TabItem>
<TabItem label="Rust">

```rust
use fznso::{LayeredModel, OwnedValue, RangeList, Type, TypeBase};

let var_int = Type::new(TypeBase::FznsoTypeBaseInt).decision(true);
let mut model = LayeredModel::default();
let x = model.add_decision(
    var_int,
    OwnedValue::IntSet(RangeList::from(1_i64..=10)),
    Some("x".into()),
    false,
    true,
    vec![],
);
let y = model.add_decision(
    var_int,
    OwnedValue::IntSet(RangeList::from(1_i64..=10)),
    Some("y".into()),
    false,
    true,
    vec![],
);
// x + y <= 12
let _ = model.add_constraint(
    "int_lin_le",
    vec![
        OwnedValue::IntList(vec![1, 1]),
        OwnedValue::List(vec![OwnedValue::Decision(x), OwnedValue::Decision(y)]),
        OwnedValue::Int(12),
    ],
    None,
    vec![],
);
model.set_objective(Some("int_maximize"), OwnedValue::Decision(x), vec![]);
```

</TabItem>
<TabItem label="C++">

```cpp
const fznso::Type INT_VAR = fznso::Type{FznsoTypeBaseInt}.decision(true);

fznso::LayeredModel model;
fznso::Decision x = model.add_decision(INT_VAR, fznso::OwnedValue::int_range(1, 10), "x");
fznso::Decision y = model.add_decision(INT_VAR, fznso::OwnedValue::int_range(1, 10), "y");
// x + y <= 12
model.add_constraint("int_lin_le", {fznso::OwnedValue::int_list({1, 1}),
                                    fznso::OwnedValue::list({fznso::OwnedValue{x},
                                                             fznso::OwnedValue{y}}),
                                    fznso::OwnedValue{std::int64_t{12}}});
model.set_objective("int_maximize", fznso::OwnedValue{x});
```

</TabItem>
</Tabs>

If your application already holds the problem in its own structures, implement [the model interface](../../spec/model/) over them rather than copying into a `LayeredModel`.
That is what the callback design is for.

:::caution
A custom model returns values **by borrow**.
Return objects the model owns and keeps alive for the whole run, not freshly built temporaries.
:::

## 4. Create, configure, run

One instance holds one configuration and whatever search state survives between runs.
Create several to search several problems at once; instances share nothing.

<Tabs syncKey="lang">
<TabItem label="Python">

```python
solver = lib.create_solver()
solver.option_set("time_limit", 30_000)   # milliseconds
solver.option_set("threads", 8)
solver.option_set("intermediate", True)   # report improving solutions as they are found

best = None

def on_solution(sol):
    global best
    best = (sol[x], sol[y])               # copied out — see the warning below
    print("found", best, "nodes:", sol.statistic("nodes"))

status = solver.run(
    model,
    on_solution=on_solution,
    on_message=lambda scope, value: print(f"[{scope}] {value}"),
)
```

</TabItem>
<TabItem label="Rust">

```rust
let mut solver = lib.create_solver();
solver.option_set("time_limit", (&30_000_i64).into())?;   // milliseconds
solver.option_set("threads", (&8_i64).into())?;
solver.option_set("intermediate", (&true).into())?;

let mut best = None;
let status = solver.run(
    &model,
    &mut |sol: &fznso::DynSolution<'_>| best = Some(sol.value(0).get_int()),
    Some(&mut |scope: &str, value: fznso::Value<'_>| eprintln!("[{scope}] {value:?}")),
    fznso::dont_interrupt(),
);
```

</TabItem>
<TabItem label="C++">

```cpp
fznso::DynSolver solver = lib->create_solver();
solver.option_set("time_limit", fznso::OwnedValue{std::int64_t{30000}});  // milliseconds
solver.option_set("threads", fznso::OwnedValue{std::int64_t{8}});
solver.option_set("intermediate", fznso::OwnedValue{true});

std::optional<std::int64_t> best;
fznso::Status status = solver.run(
    model,
    [&](const fznso::Solution& sol) { best = sol[x].as_int(); },
    [&](std::string_view scope, const fznso::Value& v) {
        std::cerr << '[' << scope << "] " << v.as_string() << '\n';
    });
```

</TabItem>
</Tabs>

Setting an option the solver did not declare fails and carries a message; the common options are in the [registry](../../registry/options/).

:::danger
The solution handed to your callback is valid **only until that callback returns**.
Copy out every value you want to keep.
Storing the solution object and reading it later reads freed memory — the Python bindings detect this and raise, Rust and C++ cannot.
:::

## 5. Read the outcome

`run` returns one of three [statuses](../../spec/running/#status): `Complete` (the search finished — with an objective, the last solution reported is optimal), `Incomplete` (it stopped early, so what you have is valid but not necessarily best), or `Error`.

Solver-scoped statistics stay readable after the run:

<Tabs syncKey="lang">
<TabItem label="Python">

```python
print(solver.statistic("nodes"), solver.statistic("solve_time"))
```

</TabItem>
<TabItem label="Rust">

```rust
println!("{}", solver.statistic("nodes").get_int());
```

</TabItem>
<TabItem label="C++">

```cpp
std::cout << solver.statistic("nodes").as_int() << '\n';
```

</TabItem>
</Tabs>

## 6. Stopping early

For a deadline set [`time_limit`](../../registry/options/); for anything a deadline cannot express — a cancel button, "five solutions is enough" — pass a `should_stop` predicate.
[Stopping early](../../spec/running/#stopping-early) covers why the first is not a special case of the second.

<Tabs syncKey="lang">
<TabItem label="Python">

```python
stop = threading.Event()
solver.run(model, on_solution=cb, should_stop=stop.is_set)
```

</TabItem>
<TabItem label="Rust">

```rust
let stop = AtomicBool::new(false);
solver.run(
    &model,
    &mut on_solution,
    fznso::ignore_messages(),
    Some(&|| stop.load(Ordering::Relaxed)),
);
```

</TabItem>
<TabItem label="C++">

```cpp
std::atomic<bool> stop{false};
solver.run(model, on_solution, [](std::string_view, const fznso::Value&) {},
           [&] { return stop.load(std::memory_order_relaxed); });
```

</TabItem>
</Tabs>

`should_stop` is the one callback you must make [thread-safe](../../spec/threading/#should_stop-may-be-called-concurrently); reading an atomic flag, as above, already is.
